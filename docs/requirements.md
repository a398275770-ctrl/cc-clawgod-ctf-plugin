# 项目需求：CT Attack-Defense 插件（cc-clawgod-ctf-plugin）

- 状态：已确认（用户逐条交互确认，见「决策记录」）
- 日期：2026年10月14日

## 1. 项目目标

把一份 56 KB 的 CTF/AWD 攻防系统提示词（源文件：`CT Attack-Defense Prompt v3.0`，含 00-内核 / 01-红队块 / 02-蓝队块 / 03-速查表）从「手工粘贴进系统提示词」改造为 **Claude Code / clawgod 插件**，通过 hook 机制**确定性注入**场景上下文，让模型在任何时刻清楚自己在什么场景工作（红队/蓝队/裁判），并更严格地遵守提示词的执行纪律。

**核心痛点**：用户（CTF 初学者）不知道什么时候该用红队模式、什么时候该用蓝队模式——插件必须**自动路由**。

## 2. 架构：三层注入

| 层 | 载体 | 内容 | 时机 |
|---|---|---|---|
| ① 常驻场景层 | SessionStart hook（matcher: `startup\|resume\|clear\|compact`） | 内核十条执行规则精简版 + 红/蓝/裁判判定表 + 优先级声明 + 首次使用引导，~3 KB（上限 10,000 字符内） | 每次会话开始；clear/compact/resume 后自动重注入——纪律永远在场 |
| ② 每轮路由层 | UserPromptSubmit hook | 读取用户 prompt，按全赛道关键词表匹配；命中红/蓝/裁判/crypto/misc 等场景时注入「当前场景 + 该赛道关键纪律」；不命中保持安静 | 每轮 prompt 提交；只对当轮生效 |
| ③ 深度参考层 | 3 个 model-invoked Skill（内核全文 / 红队块 / 蓝队块） | 模块全文 + 交付契约模板 + few-shots | 模型按 description 按需拉取；调用后跨轮保持 |

三层互为兜底：第②层 miss 时第①层判定表在场由模型自行路由；第③层承载大块内容（56 KB 全文不可能一次注入，10,000 字符是硬上限）。

## 3. 开关机制（软开关）

- 状态文件放 `${CLAUDE_PLUGIN_DATA}`（跨插件更新持久）。
- 每个 hook 脚本开头检查开关；off 时静默退出（零开销）。
- 已注入的上下文无法中途机械清除（写进 transcript 了）；off 后不再注入，彻底干净靠 `/clear`（SessionStart 重新触发时 hook 检查开关，off 则不注入）。

## 4. 命令（利用客户端原生补全，插件名 `ctf`）

| 命令 | 说明 |
|---|---|
| `/ctf:on` | 开启 CTF 攻防场景注入 |
| `/ctf:off` | 关闭场景注入 |
| `/ctf:red` | 强制红队模式 |
| `/ctf:blue` | 强制蓝队模式 |
| `/ctf:status` | 查看当前场景与开关状态 |

## 5. 范围内的需求清单（用户确认）

- [x] A1：注入文本含**优先级声明**（本场景规则与默认行为的协调）
- [x] B4：**状态可见**——注入发生时通过 `systemMessage` 让用户可感知
- [x] B5：**首次使用引导**——首启注入带 3~5 行迷你说明
- [x] B6：**全赛道关键词表**——覆盖 crypto / misc / 逆向 / 取证，不只红蓝二分
- [x] B7：**多任务不串味**——场景切换时注入「场景已从 X 切到 Y」
- [x] 源文件**乱码修复**：GBK→UTF-8 字节级还原，转换清单交用户过目；原件存 `docs/references/`
- [x] 跨平台：Windows / Linux / macOS 全适配；hook 全部 `node` 直调（不写 bash/ps1）；路径用 `path` 模块；stdin/stdout 显式 UTF-8
- [x] clawgod 兼容：已验证 clawgod 与官方 Claude Code 共用同一套插件机制（同一 `~/.claude`），无需适配层

## 8. 技术栈结论（§3.2 交互确认，五项齐全）

| 项 | 结论 | 来源 |
|---|---|---|
| 目标平台形态 | Claude Code 插件（官方 + clawgod 封装通用） | 用户明确（「做成 claude/clawgod 插件的形式」）+ 本机 clawgod 验证 |
| 语言 | 纯 Node.js（零运行时依赖，≥18） | 用户在三候选（Node 零依赖 / TypeScript / Bash+PS1）中选择 A |
| 框架 | Claude Code 插件标准形态（`.claude-plugin/plugin.json` + `hooks/hooks.json` + `skills/` + `commands/`） | 随平台形态确定，用户确认 marketplace 发布 |
| 包管理器 | 无（零运行时依赖；无 lock 文件） | 同上 |
| 构建方式 | 无构建步骤，`node` 直跑 hook 脚本 | 同上 |
| 发布 | marketplace 发布（`.claude-plugin/marketplace.json`） | 用户明确（「是走 marketplace 发布」） |

## 9. 决策记录（交互式确认，逐条落盘）

| 2 | 技术栈三候选 | 选 A：纯 Node.js 零依赖 |
| 3 | 安装范围 | 走 marketplace 发布 |
| 4 | clawgod 兼容方式 | （用户不确定，AI 查证本机后判定：同一套插件机制，无需适配层，用户认可） |

| 6 | 路由判定依据 | 用户无法判断，授权 AI 通读提示词后提方案 → 确认三层方案 |
| 7 | 关键词记忆负担 | AI 澄清：词表是机器读用户，用户无需记忆；miss 有两层兜底 |
| 8 | 开关与上下文清理 | 采纳软开关方案（off 后不注入，/clear 彻底清） |
| 9 | AI 提需求清单 | A2/A3/D11 去除，其余全要 |
| 10 | 命令设计 | 简化人性化，靠客户端原生补全 |
| 11 | 跨平台适配 | 要求 Windows/Linux 适配（AI 确认 macOS 同样覆盖） |
