# 设计规范

## 插件 UI 文案

- 面向 CTF 初学者：中文、短句、不堆术语；`systemMessage` 一行说清发生了什么
- 命令 description：动词开头、≤30 字（补全列表空间有限）
- 注入文本：标题行用 `[CTF ...]` 前缀便于模型与用户识别来源

## 注入文本原则

- 常驻层只放「每次都需要」的内容；一切可查的东西给 Skill 索引指针
- 路由层 hint ≤ 500 字符：场景要点 3-4 条 + 深入指针
- 优先级声明必须存在（A1 需求），但不得指令模型绕过真实权限确认

## 路由词表维护

- 词表来源必须可追溯：源提示词 §3.2/§1.2/§4.1
- 新增关键词须附测试用例（tests/hooks.test.js router 覆盖抽查）
- 红蓝歧义词（如 webshell）按「动词定场景」拆分：攻击动词归 red、防御动词归 blue
