# 核心信念（智能体优先的操作原则）

1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在。
5. 强制不变量，不微观管理实现。
6. 中央强制边界，本地允许自主表达。
7. 纠错成本低，等待成本高。
8. 技术债是高息贷款，小额高频偿还。
9. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。

## 本项目特定信念

12. **注入是确定性控制**：hook 注入的上下文由 Claude Code 机械执行，不依赖模型自觉——这是本插件存在的原因（用户需求：强化场景、强化遵守）。来源：Harness engineering（OpenAI，2026-02-11）方法论 + Claude Code 官方文档。
13. **上下文有硬上限**：hook `additionalContext` 上限 10,000 字符，超限内容对模型不可见——分层注入不是设计偏好，是硬约束。
14. **三层互为兜底**：常驻层（SessionStart）、路由层（UserPromptSubmit）、参考层（Skill）缺一层，场景识别就有缺口。
15. **用户是 CTF 初学者**：一切交互设计（命令补全、状态可见、首次引导、无需记忆关键词）都以此为前提。
16. **技术栈结论回溯到用户确认**：每一条技术栈决策都能回溯到 `docs/requirements.md` §8/§9 的用户确认记录，没有一条是 AI 自行假设的。
